# Chips Casino — Art Pipeline

Everything the casino mod draws is generated by **one deterministic Python
script**. No binary blob is hand-edited; re-running the script reproduces the
entire set byte-for-byte (verified: 58 file hashes unchanged across a re-run).

```bash
python3 -m venv .venv/casinoart
.venv/casinoart/bin/pip install pillow numpy
```

**No ComfyUI, no diffusion model, no network downloads.** This was a deliberate
choice, not a fallback after a failure: every asset here is geometric (frames,
bevels, discs, lattices, pin grids), and at 16x16–256x256 a diffusion model loses
to explicit pixel control. It also means the build cannot break on a checkpoint
download, and the output is reproducible. **All 29 assets are procedural.**

## 3. `casino_frame.png` — nine-slice border inset

> ## **9-slice inset = 24 px**

The image is 256x256 with a uniform **24 px** border on all four sides. Pass `24`
to the Java nine-slice routine as the left/top/right/bottom border width.

Structure is a pure function of the distance from the nearest image edge, so each
edge strip is *uniform along its length* and stretches without smearing. This is
asserted, not assumed:

```
top strip distinct columns : 1     left strip distinct rows : 1
centre unique colours      : 1     (#0F0C0A light / #070708 dark)
corner colours (TL/TR/BL/BR): 17/21/21/20   <- ornate, non-uniform
```

Simulated nine-slice stretches to 400x300, 180x140 and 600x520 produce no
transparent pixels and no edge distortion.

## 4. Palettes

Two independent 41-colour palettes. **Every opaque pixel in every file is one of
these exact values** — all shading passes through `mix()`/`mul()`, which snap to
the nearest palette entry, and `save()` hard-fails on any off-palette pixel. That
is what keeps 29 assets cohesive by construction.

## 5. Rendering rules

1. **Binary alpha only.** Every pixel is `A=0` or `A=255`. Shapes are sampled at
   pixel centres — exact nearest-neighbour behaviour — so there are no
   semi-transparent fringes on the 16x16 or 20x28 pixel art. `save()` asserts it.
2. **Palette-locked shading.** `mix(a,b,t)` and `mul(c,f)` snap to the palette, so
   bevels can never drift off-palette.
3. **One light direction.** Top-left on every bevel: highlight up-left, shadow
   down-right. On `casino_frame.png` the top/left edges use the lit gold ramp and
   bottom/right use a pre-dimmed brass ramp — same profile, toned down.
4. **No dither noise on small art.** Flat bands instead of dithered gradients,
   because dither at 16x16 reads as static.
5. **GUI sprites respect the text drawn over them** (see §6).

## 6. Layout constraints baked in from the Java

`BaseCasinoScreen` draws text on top of these sprites, so the art leaves room:

- **header_bar.png** — title at `(x+10, y+8)` and balance at `(x+10, y+20)`, both
  drawn *over* the sprite. Rows 8–29 are therefore a calm dark plate with no
  bright pixels, and all gutter detail is confined to `x <= 8`, left of the `x=10`
  text origin. The gold rail occupies only rows 0–7.
- **balance_bar.png** — coin glyph within `x <= 11`, gutter divider at `x = 12`;
  the rest is a quiet plate for the balance string.
- **cards/card_front.png** — deliberately blank; rank is drawn at `(x+3, y+3)`,
  suit at `(x+3, y+14)`. No inner rule or grain that would read as dirt under
  the pips.
- **chip.png** — 16x16 drawn at native size: 4 white edge dashes, dark inlay
  ring, gold centre pip.

## 2. Regenerating

```bash
source .venv/casinoart/bin/activate
python3 tools/gen_casino_art.py            # writes all five trees (145 files)
python3 tools/asset_sync_check.py          # asserts the five trees agree
python3 tools/verify_jars.py               # asserts the packaged artifacts
```

`gen_casino_art.py` writes into **every** project tree listed in `RESOURCE_ROOTS`,
not just `mc26.3`. That matters: the five projects are separate Gradle builds with
their own resource directories, and before this was fixed only `mc26.3` was ever
regenerated — the four 1.20.1 trees silently kept the art they were first scaffolded
with. Same filenames, different pixels, depending on which jar you opened.
`tools/asset_sync_check.py` now fails the build if that ever happens again.

### Block textures and legibility

At 16×16 a texture has to be identifiable by *silhouette*: there is no room for
detail, and a one-pixel outline on felt disappears into the felt noise. Three
textures were rewritten for this reason:

| Texture | Before | After |
|---|---|---|
| `blackjack_table` | two 3×4 outline frames — read as nothing | two solid cream cards with a black and a red pip |
| `baccarat_table` | faint 1px grid — vanished into the felt | three filled betting boxes with coloured header bars (PLAYER / BANKER / TIE) |
| `texas_holdem_floor` | felt speckled with dots and a dotted frame | the five community cards of the board across the centre |

The rule that came out of it: draw the *icon* of the game, solid, large, and centred —
not its real-world layout diagram, which is linework and therefore invisible at this size.
